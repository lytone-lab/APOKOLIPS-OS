THE VISION
------------------------------------------------------------------------
- Build a Linux distro from scratch: "Apokolips OS"
  GitHub: lytone-lab/APOKOLIPS-OS
- Styled to look like macOS 27 "Golden Gate" — but coded custom in
  C++ / Qt. NOT a macOS skin. NOT Windhawk. NOT Rainmeter.
  Everything baked into the OS itself.
- macOS + Windows hybrid: adopt macOS layout (sidebar + cards),
  Windows feature breadth (inline toggles, broader categories).
- Rule of the build: NO HALF-BAKED APPS. Every control either:
    (a) actually does something, or
    (b) is clearly marked "not yet wired" / "Coming soon"
  No mockups. No placeholders that look real but do nothing.
- User is a 1st-year IT student. Cannot code yet.
  Step-by-step instructions, one step at a time, wait for confirmation.
  Do not dump big multi-step changes without approval.

ENVIRONMENT
------------------------------------------------------------------------
- Host: Windows 11 (i5-5200U, 8GB RAM)
- VM: VirtualBox, Ubuntu (was Arch — dropped)
  VM: 3GB RAM, 2 CPU, 40GB disk
- Compositor: sway (Wayland). TTY is fine; sway IPC works when
  SWAYSOCK is exported.
- Shell runs as systemd --user service:
  ~/.config/systemd/user/apokolips-shell.service
  ExecStart=/home/lytone/apokolips-shell/build/apokolips-shell
- User codes via VS Code Remote-SSH (port forward on host 2222 →
  guest 22). No VM terminal copy-paste of code anymore.
- No Bluetooth hardware in the VM.
- No Wi-Fi adapter in the VM (only enp0s3 ethernet).
- Battery present (virtual BAT0 in VirtualBox).

MANDATORY APP CHECKLIST (every new app or app redesign)
------------------------------------------------------------------------
An app is NOT done until all of these are verified working. No
exceptions. This applies to AI #1, Manus, and any future AI.

  [ ] Traffic lights — present, macOS order (red / yellow / green),
      on the LEFT. Correct hover colors. Close/min/max all wired.
  [ ] Running dot — the white indicator dot under the dock icon
      appears when the app is running and disappears on quit.
      Fix: launch with `QProcess::startDetached(program, args, "",
      &m_pid)` and store the PID via `setPid(...)`. Do NOT use a
      bare `QProcess::startDetached(...)` followed by `return;` in
      the dock click handler — that skips the PID capture.
  [ ] Logo / mark — draws correctly on the dock icon at 22px and in
      the launcher at 52px. Dispatch line in the icon renderer
      (`else if (name == "X") drawX(p, r, c);`) matches the exact
      string used in the dock apps array and launcher apps array.
  [ ] Frameless + rounded corners — Sigil rounding (14px), correct
      background, no black fringe on bottom corners.
  [ ] Initial window size — opens at a reasonable size, does NOT
      cover the dock, does NOT need a manual resize.
  [ ] Launcher tile — clickable, launches the app, correct label.
  [ ] Dock tile — clickable, launches the app, correct label.
  [ ] Core Matrix — registered as an option for relevant MIME types
      via a .desktop file in ~/.local/share/applications, with
      update-desktop-database run after.
  [ ] SVG icon — present in ~/.local/share/icons/hicolor/scalable/
      apps/ and referenced by the .desktop file via Icon=.
  [ ] Persistence — user settings (folder, shuffle, etc.) survive
      restart via visual.json.

  [ ] Genie + dock-click restore — if the app has been minimized via
      genie (win+M) it lives in sway's scratchpad. A plain
      `show()` / `raise()` from Qt will NOT recover it. The app's
      dock-click / single-instance focus handler MUST do all of:

        1. QProcess::startDetached("swaymsg",
               { "[title=\"<Window Title>\"] scratchpad show" });
        2. QProcess::startDetached("swaymsg",
               { "[title=\"<Window Title>\"] focus" });
        3. widget->show();
        4. widget->raise();
        5. widget->activateWindow();
        6. Recenter via the dock-aware geometry helper

      Apps that already have this: NONE (Settings in progress).
      Apps that need it: Settings, Finder, Aperture, BoomTube,
      Notes, Calculator, DemoWindow, any future shell app.

  [ ] Single-instance launch — spawn once, then send a "focus"
      message over QLocalSocket / QLocalServer on subsequent
      launches. Socket lives at /tmp/apokolips-<app> (NOT
      QLocalServer default path — we use explicit /tmp paths).

If any of these is missing, the app is bug-listed, not shipped.

BUG LIST (open)
------------------------------------------------------------------------
  1. Clipboard IPC unreliable
     QLocalServer/Socket starts, but second-instance toggle sometimes
     doesn't reach the running shell. Panel is built and works when
     toggled in-process. Parked.
  2. Finder opacity not real-time
     Settings writes visual.json but FileExplorer (separate process)
     doesn't poll it. Needs QTimer in FileExplorer to watch mtime
     and repaint. ~15 lines.
  3. Sway reload keybind Super+Shift+R doesn't fire
     Only Ctrl+Shift+R works for shell. Check sway config bindsym.
  4. Terminal (foot) decorations — no title bar / traffic lights
  5. Real per-app menus — needs our own protocol
  6. App icons — remaining line-art needs replacing
  7. Glyph tweak list (parked):
     - toolbar Save/Copy/Cancel still slightly spread
     - Enter key should save, Ctrl+C copy, Esc cancel
     - dimension label inside selection, top-left
     - rule-of-thirds guide lines while dragging
     - save notification toast
     - save path configurable
     - snap-to-window (single click selects a whole sway window)
     - delay timer (Super+Shift+D → 5s delay)
     - filename pattern configurable
     - Settings → Glyph page
  8. QString::arg missing argument warnings (harmless, in logs)
  9. Launcher Arc Reactor tile doesn't use reactor mark yet
 10. Shell windows — black fringe on rounded corners
     Wallpaper shows through at the outer antialiased edge as a dark
     band. Tried and FAILED:
       - Source composition clear + direct fillPath
       - setMask(QRegion(rounded path))
       - AA saturation strokes (3 clipped stroke passes with opaque
         section colors)
     Root cause: client-side rounded corners + WA_TranslucentBackground
     under sway. Antialiased edge pixels render over black instead of
     wallpaper.
     REAL FIX (V2): migrate shell windows to zwlr-layer-shell protocol
     so the compositor handles the surface. Major rewrite. Deferred.

     STATUS: accepted as a known V1 cosmetic limitation.

AI WORKING RULES (very important)
------------------------------------------------------------------------
- Read this file first.
- Read any pasted transcripts carefully before responding.
  Do NOT claim you read something you didn't. Do NOT fabricate
  memory of a conversation. If you missed it, say so.
- One change at a time. Build-verify between steps.
- For any feature: first read the discussion text where the user and
  previous AI talked about it, confirm understanding, THEN proceed.
- Backup files before editing: cp main.cpp main.cpp.pre-<feature>
  Use timestamped backups when chaining.
- Patches should be Python scripts that:
  - use exact-string anchors on main.cpp
  - print OK: <label> / MISS: <label> per replacement
  - abort (with "--- not writing ---") if any anchor misses
  - make a timestamped backup before write
- Never claim something is "better" before it compiles and the user
  has seen it run.
- Ownership rule: only one AI edits main.cpp at a time. Hand back
  explicitly with a handoff message that lists:
    - what changed
    - new classes / methods / signatures
    - sway config changes
    - any genie / animation side-effects
  The other AI stays OUT until handback.
